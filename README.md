Выполнены только этапы 1–3. Консольная программа загружает CSV VFS
в память, исполняет стартовый скрипт и принимает команды в REPL.

Этапы 4–5 и практическая №2 в эту реализацию не входят.

## Установка и запуск

Нужен Python 3.10 или новее. Внешних библиотек и сборки нет.
Из корня репозитория:

```console
python src/main.py
python src/main.py --vfs-path test_data/vfs_deep.csv
python src/main.py --vfs-path test_data/vfs_files.csv --script-path test_data/success.txt
python src/main.py --help
```

Windows: `run.bat --vfs-path test_data/vfs_deep.csv`.
Bash: `bash run.sh --vfs-path test_data/vfs_deep.csv`.
Обёртки переключаются в каталог проекта, поэтому относительные пути в них
считаются от корня проекта. При прямом запуске Python — от текущего каталога.
Пути параметров командной строки можно заключать в кавычки.

## Этап 1: REPL

Приглашение содержит имя CSV без расширения, по умолчанию `default_vfs`.
Парсер разделяет ввод по пробельным символам. Кавычки, подстановка переменных,
перенаправления и пути с пробелами внутри команд эмулятора не поддерживаются.
Пустая строка пропускается. Ошибка выводится в stderr и не завершает REPL.
`exit`, EOF (Ctrl+Z, Enter в Windows / Ctrl+D в Unix) и Ctrl+C завершают сеанс.

| Команда | Поведение |
| --- | --- |
| `ls [путь]` | Печатает имя и список аргументов; 0–1 аргумент |
| `cd путь` | Печатает имя и список аргументов; ровно 1 аргумент |
| `exit` | Выход; аргументы запрещены |
| `vfs-save путь` | Сохраняет VFS в CSV; ровно 1 аргумент |

Пример интерактивной демонстрации:

```text
default_vfs> ls
[STUB] ls called with args: []
default_vfs> cd /home
[STUB] cd called with args: ['/home']
default_vfs> cd
Error: cd: invalid arguments
default_vfs> unknown
Error: unknown command 'unknown'
default_vfs> exit
Goodbye!
```

## Этап 2: конфигурация

- `--vfs-path PATH`: CSV VFS; без параметра создаётся корневой каталог в памяти.
- `--script-path PATH`: стартовый текстовый файл UTF-8 (BOM допустим).
- `--help`: справка.

При каждом запуске выводятся оба значения `[CONFIG]`, в том числе незаданные.
Скрипт исполняется последовательно, с отображением приглашения, команды
и результата. Пустые строки и строки с `#` в начале после пробелов пропускаются.
При первой ошибке скрипт и приложение завершаются с кодом 1, в сообщении
указаны файл и номер строки. `exit` завершает приложение с кодом 0.
Если скрипт закончился успешно без `exit`, начинается интерактивный сеанс.
Ошибки чтения и кодировки скрипта также диагностируются.

```console
python src/main.py --script-path test_data/test_script.txt
```

В этом примере `invalid_cmd` на строке 6 останавливает исполнение;
следующая команда `cd user` не выполняется.

## Этап 3: VFS

CSV в UTF-8, разделитель `;`, строго три колонки:

```csv
path;type;base64_content
/;dir;
home;dir;
home/user;dir;
home/user/data.bin;file;AAEC/w==
```

Вложенность задаётся полным путём с `/`. Корень `/` обязателен.
Пути могут быть абсолютными или относительными к виртуальному корню.
Все родительские каталоги должны присутствовать, порядок строк произвольный.
Типы: `dir` (содержимое пустое) и `file` (содержимое — base64, включая пустой файл).
Пути нормализуются, повторения после нормализации запрещены.
Компонент `..`, обратные слеши и NUL запрещены.
Отсутствующие родители, неверный заголовок, число полей, тип или base64
вызывают ошибку загрузки и код завершения 1.

Дерево и байты файлов хранятся только в памяти, ничего не распаковывается.
Единственная операция записи на диск — явная команда `vfs-save путь`.
Она записывает все каталоги и файлы в тот же CSV-формат, сортируя пути.
Существующий целевой файл перезаписывается; для сохранения исходника выбирайте
другой путь. Ошибка записи диагностируется.

```text
vfs_deep> vfs-save saved_vfs.csv
VFS saved: saved_vfs.csv
```

Файл можно снова загрузить через `--vfs-path saved_vfs.csv`.

## Проверки и демонстрационные сценарии

```console
python -m unittest discover -s tests -v
```

11 автоматических тестов проверяют CLI, ошибки аргументов, остановку скрипта,
переход в REPL, три VFS, неизменность источника, валидацию дерева и
сохранение/повторную загрузку всех значений байтов 0–255.

Сценарии ОС (запускать из корня проекта):

```console
scripts\test_windows.bat
scripts\test_vfs.bat
bash scripts/test_bash.sh
bash scripts/test_vfs.sh
```

Они демонстрируют параметры отдельно и совместно, успешные команды,
неизвестную команду, неверные аргументы, ошибки чтения и записи,
минимальную VFS, несколько файлов и дерево глубиной минимум три уровня.
Ошибочные запуски здесь намеренные. `success.txt` сохраняет `saved_vfs.csv`
в корень проекта; файл исключён из Git. Скрипты не требуют ручного ввода.

## Структура и функции

- `src/main.py`: `parse_command` — парсер, `execute_command` — диспетчер,
  `save_vfs` — служебная запись, `run_script` — выполнение сценария,
  `run_repl` — интерактивный цикл, `print_error` — диагностика,
  `main` — параметры, загрузка VFS и управление запуском.
- `src/vfs.py`: `normalize_path` — проверка пути; `VirtualFileSystem`
  хранит словарь `entries` (каталог — `None`, файл — `bytes`).
  `load` читает CSV, `add_row` проверяет запись, `validate_tree` проверяет
  структуру каталогов, `save` записывает CSV.
- `tests/test_shell.py`: автоматические тесты на стандартном `unittest`.
- `test_data/`: три корректных VFS, повреждённый CSV и стартовые сценарии.
- `scripts/`: демонстрации для Windows и Bash.

Изменения этапов сохраняются отдельными Conventional Commits;
исходный коммит этапа 1 сохранён в истории.
